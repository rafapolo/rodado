ssh beelink 'bash -s' <<'EOF'

## Passo 3 — a rota que pode desbloquear o T21 de `respostas.md`

`docs/respostas.md` marca T21-1/2/3/5 como ⏳ dando como motivo os 100 mi+ de
linhas de `cgu_licitacao_contrato`. **Existe rota barata que ninguém tinha
considerado**, achada independentemente pelo Gemma (passo 6 da sessão
`53ac1869`) e por um agente Claude:

```
br_transferegov.planos_acao   (25.969 linhas)  valor_repasse_emenda_plano_acao > 0
   ->  id_plano_acao
br_transferegov.transferencias (4.248 linhas)  cnpj_favorecido_empenho  <- CNPJ do fornecedor
   ->  CPF_CNPJ
br_tcu_inidoneos.empresas  /  br_pgfn_dividaativa.divida
```

Nunca verificada — o beelink caiu exatamente na consulta que compararia os
formatos de CNPJ das três pontas. **É a primeira coisa a rodar.** O risco
conhecido deste espelho é padding/máscara divergente (o caso `br_anp_combustiveis`),
então comece pelo formato, nunca pelo join:

```bash
ssh beelink '~/bin/duckdb -readonly -json ~/rodado/basedosdados.duckdb' <<'SQL'
SET enable_progress_bar=false;
WITH a AS (SELECT 'transferegov' AS fonte, cnpj_favorecido_empenho AS cnpj
           FROM br_transferegov.transferencias WHERE cnpj_favorecido_empenho IS NOT NULL LIMIT 3),
     b AS (SELECT 'tcu', CPF_CNPJ FROM br_tcu_inidoneos.empresas LIMIT 3),
     c AS (SELECT 'pgfn', CPF_CNPJ FROM br_pgfn_dividaativa.divida LIMIT 3)
SELECT fonte, cnpj, length(cnpj) AS n
FROM (SELECT * FROM a UNION ALL SELECT * FROM b UNION ALL SELECT * FROM c);
SQL
```

Decisão: se os três derem `n=14` sem máscara, o join é direto. Se divergirem,
normalize com `lpad(regexp_replace(cnpj,'[^0-9]','','g'), 14, '0')` nos dois
lados **antes** de contar — e registre a expressão em
`docs/context/bridges.yaml` com o `verified` do dia, senão a próxima sessão
redescobre.

Se casar, T21 sai de ⏳ e `docs/respostas.md` muda — o que também realimenta
`build_douradas_perguntas.py`.

## Passo 4 — remedir o desperdício de turno (a meta)

A meta acordada é **paridade de passos, não de velocidade**: tudo bem o Gemma
ser lento, não tudo bem gastar turno em coisa que ele já sabe. Linha de base
medida em 2026-09-04, mesma pergunta: Gemma 24 chamadas (8 sem informação
nova) contra 8 de um agente Claude.

Rodar de novo, agora com o curto-circuito idempotente no ar:

```bash
bun harness/pergunte.ts "Seguindo o dinheiro das emendas parlamentares até os contratos firmados, quantos fornecedores desses contratos estão sancionados pelo TCU ou têm dívida ativa na PGFN?" | tee /tmp/sessao.log
```

Leva até 40 min (`HARNESS_TIMEOUT_MS`). `agente.ts` imprime cada chamada de
ferramenta em stdout como `[ferramenta] nome({...})` — capture com `tee` para
medir depois, sem precisar de log de sessão à parte:

```bash
python3 - <<'PY'
import re, json, collections
linhas = open('/tmp/sessao.log').read()
c = [(m.group(1), m.group(2)) for m in re.finditer(r'\[ferramenta\] (\w+)\((.*)\)\n', linhas)]
print('chamadas:', len(c))
print(collections.Counter(nome for nome, _ in c))
visto = collections.Counter()
for i, (nome, args) in enumerate(c, 1):
    try:
        chave = (nome, json.dumps(json.loads(args), sort_keys=True, ensure_ascii=False))
    except json.JSONDecodeError:
        chave = (nome, args)
    visto[chave] += 1
    if visto[chave] > 1: print('REPETIDA na chamada', i, '->', args[:90])
PY
```

Critério de sucesso: **zero linhas `REPETIDA`**. Se aparecer alguma, o
curto-circuito não pegou aquele caso — provavelmente porque a SQL variou
cosmeticamente, e aí o alvo passa a ser a proposta 4 (instrução negativa) ou a
3 (placar no resultado), não mais a 5.

Vale promover esse trecho a `harness/analisa_sessao.ts`: `regras.md` já manda
*toda rodada terminar classificando as falhas*, e hoje isso é feito à mão toda
vez.
